## 跨图裁决

- 35 显示十个星位及评价菜单，1–9 星文字可见、6 星选中，最末项被遮挡；36 同样显示十个星位。我方采用 1–10 并提供清空状态，完整末项、键盘操作和保存细节属于自研决策，不能误实现为只有五星。
- 原菜单的 Excalidraw 项明确写“暂不支持”；用户 P2 要求实现，所以我方提供可运行目标，依赖缺失时解释禁用原因。
- Canvas / Excalidraw 的宿主画布、插件目标摘要面板、实际 `.canvas` / `.excalidraw.md` 落盘是三个不同验收对象；面板出现卡片不证明原生画布落地、跳转或反向删除。
- 章节必须形成真实 Canvas nodes/edges；摘录标题只附于插件创建的摘录，不修改用户原生空白卡片。
- 39 的分享仅是未来计划字幕；不复制未存在的分享流程，P3 Markdown / JSON 导出仍为独立必做需求。
- 23 / 63 仅记录字段与状态，不复制画面中的示例凭据、桶名或端点；无用户凭据的真实云上传验收必须明确受限。
- 工具栏模糊或用途不明的图标按“未观察到”处理，采用具名、自研的工具入口；水印、宿主通用导航及参考生态扩展可明确不做。
- 69 只有一般 Canvas 节点、不可见工具栏按钮的字幕；没有可读 AI 按钮、对话或编辑结果。AI 需求来自用户 P3 与基线笔记，可选依赖检测与实际调用需单独验收。
- 参考图同时存在深色与浅色（例如 25、44–47）表面；我方依用户 brief 验证 light / dark、常用桌面和窄面板，`isDesktopOnly=true` 不宣称移动端验证。
