## Spec：需求与正确性

### S1 · P1：等待目标锁的旧写入覆盖新标签，并报告成功

- 位置：`src/targets/TargetService.ts:28-34`；`src/annotations/AnnotationStore.ts:54-64`。实际 UI 入口为 `src/reader/ReaderExcerptController.ts:47` 的改色和 `ReaderCommentBridge.ts:43` 的标签更新。
- 触发：同一目标有一个写入尚未完成，另一条改色写入携带旧高亮进入路径队列；等待期间用户添加标签。
- 原因：`stageTargetWrite` 的 observed/before 在获得目标锁后才捕获，无法发现等待路径锁期间的变化，随后把调用时的旧整条 snapshot 写回真源。
- 复现：真实 Repository/AnnotationStore/TargetService，暂停首个目标 I/O，排队改色，再保存 `new-tag-after-queue`。放行后首写正确报告 pending，第二写报告 completed；内存与磁盘的 tags 都变成 `[]`，pending 清空。另一代理独立复跑并核对真实 UI 的浅拷贝调用，确认成立。
- 需求：ADR 0009 的“排队期间活动数据改变……拒绝旧 stage”，以及较新源数据/意图应保留。
- 修复：进入路径队列前捕获源版本，在提交闭包内验证；更稳妥的更新接口只提交本次字段变更，出队时合并最新源数据，并验证目标路径。不能只在现有 stage 内重复读取 observed。
- 验收：同一路径排队改色、改标题与并发标签/rename 交错；较新字段不丢失，过期写入不报告成功。

### S2 · P1：旧目标核验会删除排队期间迁移后的标注

- 位置：`src/targets/TargetService.ts:128`；`src/annotations/AnnotationStore.ts:199-200`、`removeIds`。
- 触发：旧目标核验生成 missing ID；删除提交等待 Repository 队列时，前序 rename 将标注迁到新路径并建立新 pending。
- 原因：真正删除时仅按 ID 操作，没有再验证路径、类型、源版本与 pending。
- 复现：迁移到 `notes/moved.canvas` 后，旧核验仍返回 removedIds；活动标注与磁盘记录消失，新 pending 被清空，标注和评论进入 `target-deleted` 回收站。属于误移入回收站，不能表述为不可恢复的永久删除。另一代理独立复跑确认。
- 需求：ADR 0009:11“只核验……相同路径、相同格式的候选，避免旧事件删除已转移的标注”；:17 待写标注不参与反向删除。
- 修复：把核验目标和版本凭据传入删除提交，在 Repository 闭包内重新检查；返回实际删除 ID。
- 验收：queued rename/relink/stage 在删除前完成时，过期核验必须跳过，新路径与 pending 保留。

### S3 · P1：缩略图耗尽共享画布预算后阻塞正文

- 位置：`src/reader/PdfCanvasBudget.ts:22-30`；`src/reader/ReaderNavigation.ts:33-36`。
- 触发：长 PDF 打开缩略图侧栏并浏览很多缩略图。
- 原因：缩略图首次可见后停止观察，但画布仍连接在 DOM；预算只回收脱离 DOM 的画布。缩略图持续占用与正文、预览、裁剪共享的 24,000,000 像素预算。
- 复现：真实 PdfRenderer/PdfCanvasBudget，PDF/DOM 替身，页尺寸 600×800、缩略图宽 148 CSS px、DPR 3。第 96 张缩略图失败，保留像素达到上限，之后正文 `renderPage(301)` 拒绝并报“PDF 画布预算不足。”该数量仅适用于该夹具，不能外推为所有设备固定阈值。
- 修复：缩略图采用可见窗口或 LRU 回收，并在淘汰后重新观察；为正文和裁剪预留预算或分池。仅提高总上限不能解决生命周期问题。
- 验收：300 页以上、DPR 2/3、混合页尺寸；遍历侧栏后继续翻页、预览和裁剪。

### S4 · P2：完整备份导出成功，恢复入口却因体积拒绝

- 位置：`src/ui/portability/PanelSection.ts:111`；`src/ui/portability/BackupRestorePanel.ts:98`。
- 需求：调研报告要求带 schemaVersion 的“完整备份/恢复”。
- 复现：真实备份服务导出 2500 条各 1600 汉字摘录，生成 13,426,094 bytes 合法备份。服务可以解析自己的输出，但恢复界面共用文献读取函数，超过 10 MiB 即报“请分批处理”。完整备份没有对应的分批协议。
- 修复：为备份恢复设计独立容量策略与资源保护，保证支持的自产备份可由 UI 回读；不能仅依赖服务层 JSON 往返测试。
- 验收：导出包含标注、评论和删除记录的大型备份，经过真实文件入口预览、确认、恢复。

### S5 · P2：文献预览承诺跳过冲突，确认后却整批失败

- 位置：`src/ui/portability/BibliographicImportPanel.ts:18`；`src/portability/ReadingDeskDataManagement.ts:65`。
- 触发：一条已确认附件的有效条目与一条身份冲突条目一起导入。
- 复现：预览显示 1 条可应用、无解析错误，界面说明“无附件和冲突条目会跳过”；点击后服务因为任一 conflict 阻止全部导入。
- 影响：用户按预览操作仍无法完成看似允许的导入。冲突保护本身合理，错误是界面契约与执行策略不一致。
- 修复：实现显式选中/跳过冲突，或让文案、按钮禁用条件和可应用数量一致表达整批阻断。

### S6 · P2：连续模式跨页边界的历史位置恢复不准确

- 位置：`src/reader/ReaderPositionController.ts:32-33`。
- 原因：当前页按视口中心确定，该页顶部可在视口顶部下方；捕获却把有效的负页内偏移裁成 0。
- 复现：页高 100、间距 16、视口高 100、scrollTop=80，当前中心页是第 2 页。跳第 8 页再后退，返回 116 而非 80。
- 修复：历史锚定视口顶部所在页，或保存相对中心页的有符号偏移；与位置类型/归一化规则一起调整。
- 验收：跨两页的视口、混合页尺寸、缩放后后退/前进。

## Standards：规范与界面

### T1 · P2：分类和视图缺少插件提供的选中反馈

- 位置：`src/views/ShelfView.ts:84`、`:119`；`assets/styles.css:446`。
- 新实现只更新 aria-pressed，移除了 is-selected 和视图切换类；现存 CSS 仍依赖这两个类。
- 隔离 DOM 证明选中分类和视图均不匹配选中规则。宿主主题可能有额外样式，但插件自身的确定性状态反馈已断开。
- 修复：同步状态类，或将作用域内选中规则绑定 `[aria-pressed='true']`；同时核验明暗主题、键盘焦点与选择状态的区别。

## 既有问题：表格编辑草稿会在另一次保存结束时丢失

这是基线已有的全量重绘风险，本次新增标题编辑延续了它，不计入以上新增问题数量。

复现：标题 blur 开始异步保存，用户立即在作者字段输入 Draft author；标题保存结束触发 reload/paint，作者控件重建为 Old author。焦点恢复了，草稿却没有保存。建议稳定更新控件或按书目/字段保存独立草稿，不能只恢复焦点和光标位置。

## 下一阶段功能与优化

建议 0.4.1 先完成 S1–S6、T1 和草稿保护；T2/T3 可合并修复。以下功能按实际阅读收益推进：

1. **自动恢复快照管理。** `main.ts:434-440` 每次覆盖写出完整原件，ADR 0008 明确本轮不自动删除。增加空间/数量统计、按时间分层保留、恢复索引与清理预览；不要直接关闭原件保护。常规进度写入也应纳入容量与 I/O 压测。
2. **补齐阅读列表管理并保存研究现场。** LibraryIndex 已有 renameList/deleteList，接通 UI；保存视图、组合筛选与页码。先补完整现有工作流，再考虑智能列表。
3. **精确位置持久化与命名书签。** 基于修正后的历史位置模型，重开文档回到准确页内位置，支持本书命名书签和快速跳转。
4. **PDF 页码标签。** 区分 PDF 物理页、罗马数字前言及印刷页码，并在跳转、复制引用和摘录模板保持一致，减少学术引用手动换算。
5. **导入/恢复的逐项决策。** 文献预览支持选中导入、跳过冲突和批量确认附件；恢复提供逐对象差异及显式处理 active/deleted 冲突的入口。继续保持恢复确认后再次检查版本。
6. **源文件变更与锚点诊断。** 在同路径 PDF 被替换后显示标注对应文件版本是否变化，提供文字上下文辅助定位；保留归一化 rects[] 为几何真源，不能自动把旧坐标当作新文档上可靠的位置。

暂不优先扩大到云同步、OCR 或大型 AI 功能；当前最有价值的投入是补强恢复、长文档生命周期和连续操作体验。
